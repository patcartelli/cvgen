src/schema/resume.ts required exports:
- `export const ResumeSchema` — Zod object with these top-level keys:
  - contact: ContactSchema (all 6 fields required)
  - summary: z.string().optional()
  - coreCompetencies: z.array(z.string()).optional()
  - experience: z.array(ExperienceSchema)
  - education: z.array(EducationSchema)
  - skills: z.array(SkillGroupSchema)
- `export type ResumeData = z.infer<typeof ResumeSchema>`

ContactSchema (D-09 — all required, all z.string()):
  name, email, phone, location, linkedin, github

ExperienceSchema (D-10):
  role: z.string(), company: z.string(), startDate: z.string(), endDate: z.string(),
  type: z.enum(["full-time", "contract"]).optional(),
  bullets: z.array(z.string())

EducationSchema (D-11):
  degree: z.string(), institution: z.string(), year: z.string()

SkillGroupSchema (D-12):
  category: z.string(), items: z.array(z.string())

Internal (schema submodules): ContactSchema, ExperienceSchema, EducationSchema, SkillGroupSchema — these can be non-exported const declarations inside src/schema/resume.ts; downstream phases only import ResumeSchema and ResumeData.

src/schema/validate.ts required export:
- `export function validateResume(data: unknown): ResumeData` — thin safeParse wrapper; on failure throws Error with a placeholder message (Phase 2 replaces with human-readable section-naming errors per PARSE-03).

src/cli/index.ts contract:
- First line MUST be `#!/usr/bin/env node` (bin entry per package.json bin.cvgen → dist/cli/index.js)
- Prints a stub message and exits 0

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Information Disclosure | Real personal data in fictional fixture files | mitigate | Fixture identity is `Alex Rivera` with @example.com email (reserved-for-docs domain); acceptance criteria explicitly forbids the user's real contact data; reviewed at commit time |
| T-01-05 | Tampering (input validation) | `validateResume` accepts arbitrary `unknown` input from later phases | mitigate | Zod `safeParse` is used (not `parse`); function signature `(data: unknown): ResumeData` forces callers through the validation gate; wrong-shape inputs throw before reaching downstream code |

| T-01-07 | Tampering | Fixture placeholder string accidentally matches a real API key pattern | mitigate | Fixtures contain no API-key-shaped strings anywhere; gitleaks hook (activated in Plan 03) is a second-layer check before the first fixture commit |
</threat_model>
