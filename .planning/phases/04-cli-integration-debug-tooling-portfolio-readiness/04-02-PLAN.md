<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argument → file system | `<file>` argument is resolved via `resolve()` before readFile |
| CLI argument → file system (init) | `[output]` argument written with `flag: 'wx'` (exclusive create) |
| Claude API response → stdout | rawResponse printed only when `--verbose` is set; never on default path |
| Markdown resume content → HTML → PDF | `escapeHtml()` already applied in render.ts; no new HTML surface in Phase 4 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03 | Information Disclosure | `--verbose` output | mitigate | rawResponse is printed to stderr only, never stdout; gated behind `options.verbose` check; `ANTHROPIC_API_KEY` value is never included in the rawResponse payload (it is an HTTP header, not echoed in the SDK Message object) |
| T-04-04 | Tampering | `<file>` path traversal | mitigate | `resolve(file)` normalizes the path and resolves symlinks before readFile; no directory walk; only the exact resolved path is read |
| T-04-05 | Tampering | `cvgen init` clobber | mitigate | `writeFile(..., { flag: 'wx' })` uses exclusive create — EEXIST is caught and surfaces as a human-readable error; existing resume notes cannot be silently overwritten |
| T-04-06 | Tampering | HTML injection via resume fields | accept | `escapeHtml()` is already applied in render.ts templates (shipped in Phase 3); no new HTML template surface is introduced in Phase 4 |
| T-04-07 | Elevation of Privilege | Commander strict mode | accept | Commander 15 is strict by default — unknown options and missing required arguments are rejected with an error and exit 1; no `.allowUnknownOption()` is used |
| T-04-SC | Tampering | npm installs | accept | No new npm installs in Plan 02; `commander` was installed and audited in Plan 01 |
</threat_model>
