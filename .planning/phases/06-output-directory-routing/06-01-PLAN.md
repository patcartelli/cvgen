<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → toCompanySlug | Company name string enters from stdin; must not produce path traversal sequences in the output slug |
| slug → filesystem path | The slug is joined into `join(process.cwd(), 'output', slug)` in the CLI layer; traversal sequences in the slug would escape the output/ directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | `toCompanySlug` — path traversal via company name | mitigate | The regex `/[^a-zA-Z0-9 ]/g` strips all non-alphanumeric/non-space characters including `/`, `.`, `\`, and `-`. After stripping, the only remaining characters are alphanumeric and spaces (converted to hyphens). A traversal sequence like `../etc/passwd` becomes `etcpasswd` — no slash, no dot survives. Verified in behavior tests (all-special input returns empty string). |
| T-06-02 | Elevation of Privilege | Empty slug after stripping | mitigate | Plan 02 guards on empty slug via `program.error("Company name must contain at least one letter or digit.", { exitCode: 1 })` — prevents a silent fall-through to `output/` when the user said "yes, tailored". |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | This phase installs zero external packages. All capabilities use Node built-ins already in node_modules. No package legitimacy gate required. |
</threat_model>
