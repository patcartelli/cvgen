<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stdin → outputDir | The readline prompt accepts a free-form company name string from stdin; the slug function sanitizes it before the string is used in a filesystem path. |
| outputDir → fs.mkdir | The sanitized outputDir is passed directly to mkdir; if the slug function failed to sanitize, a traversal path could escape output/. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Tampering | `toCompanySlug` path traversal via stdin (CLI layer call site) | mitigate | `toCompanySlug` strips `/`, `\`, `.`, and all non-alphanumeric/non-space characters via `/[^a-zA-Z0-9 ]/g` before producing the slug. A traversal sequence like `../secrets` becomes `secrets` — the parent-traversal component is gone. Confirmed in Plan 01 unit tests (T-06-01). The CLI layer calls `toCompanySlug(company.trim())` and guards on empty result with `program.error()`. |
| T-06-04 | Denial of Service | Long company name input causing extremely long path | accept | Node's path.join with 255-char per-segment FS limits applies. An exceptionally long company name would produce a long-but-still-alphanumeric slug. The output/ root anchors the path to cwd. No unbounded buffer risk. Low-value target (local CLI, single user). |
| T-06-05 | Information Disclosure | outputDir written to console.log in existing "Written: ..." line | accept | The CLI already logs written paths. Disclosing the output path to the terminal user is the intended behavior. No PII beyond cwd is exposed. |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | This plan installs zero external packages. All capabilities use Node built-ins already present. No package legitimacy gate required. |
</threat_model>
