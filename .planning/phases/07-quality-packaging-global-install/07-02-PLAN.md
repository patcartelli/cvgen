<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer machine → global npm bin PATH | `npm link` creates a symlink that any shell resolves; only trusted user code runs |
| Repo → npm registry (future) | If ever published, prepack rebuilds dist/ from current source before tarball; ensures tarball matches HEAD |
| README prose → new users | Consumer-facing documentation; incorrect prose leads to wrong mental model, not security compromise |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03 | Tampering | dist/ contents at publish time | mitigate | `prepack: npm run build` guarantees dist/ is rebuilt from HEAD source before `npm pack`/`npm publish` create a tarball; stale/tampered dist/ cannot ship |
| T-07-04 | Elevation of Privilege | global bin symlink after `npm link` | accept | `npm link` is a developer-initiated action against local trusted source; no elevation beyond user-owned npm prefix; documented in README as a manual step |
| T-07-05 | Information Disclosure | README output-path prose | accept | README is public; prose describes only relative-path conventions, no secrets |
| T-07-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan (`npm run build` and `npm link` invoke existing tooling only); no supply-chain surface added |
</threat_model>
