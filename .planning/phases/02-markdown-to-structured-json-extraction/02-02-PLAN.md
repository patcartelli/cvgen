<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process.argv → CLI | Untrusted CLI input (file paths, flags) crosses into the process |
| filesystem → CLI | User-provided markdown file (path could be anywhere) is read into memory |
| process.env.ANTHROPIC_API_KEY → Anthropic client | Secret loaded from environment; must never leak to stdout/stderr/logs |
| Claude API response → stdout | Structured output printed to stdout via JSON.stringify for --validate-only mode |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Information disclosure | ANTHROPIC_API_KEY leakage via CLI logging | mitigate | Acceptance criteria enforce `grep -cE "console\.log\(process\.env" src/cli/index.ts` returns 0. Error messages reference the variable name only, never the value. `new Anthropic()` construction happens inside extract.ts (Plan 01), so cli/index.ts has no direct handle on the key value. |
| T-02-06 | Denial of service | Unbounded markdown file read via readFile(resolve(filePath), "utf8") | accept | Single-user local CLI; the user is reading their own resume file. Node's readFile will error naturally on files exceeding memory. Adding a size cap here adds friction with no security benefit for a personal tool per PROJECT.md scope. |
| T-02-07 | Elevation of privilege / path traversal | User-provided filePath via process.argv → resolve() | accept | This is a local CLI running as the invoking user with existing filesystem permissions. resolve() normalizes the path but does not sandbox — sandboxing would break the legitimate use case of "point at any .md file on my machine." No privilege boundary is crossed by reading a file the user already has access to. |
| T-02-08 | Tampering | preflightCheck bypass by malformed markdown that fools regex | mitigate | Preflight is defense-in-depth (per D-E01 — the schema is the authoritative validator). Even if preflight is bypassed, extractResume's zodOutputFormat + ResumeSchema catches invalid structure downstream (T-02-01, defined in Plan 01). Combined coverage is layered per D-E01. |
| T-02-09 | Repudiation | User claims they didn't run cvgen against a specific file | accept | No audit/telemetry requirement per PROJECT.md ("Telemetry/analytics/phone-home behavior" is explicitly out-of-scope). Not applicable to a personal tool. |
| T-02-SC | Tampering | npm installs (no new deps in this plan) | mitigate | Plan 02 adds no new dependencies. All packages used (@anthropic-ai/sdk, zod, tsx, typescript, biome) were audited in Phase 1/Phase 2 research (RESEARCH.md Package Legitimacy Audit). No install task in this plan → no slopcheck checkpoint required. |
</threat_model>
